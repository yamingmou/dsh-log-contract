# 机制六层模型（本线，对标共同体 bug 线）

| 层 | 是什么 | 本线落点 |
|---|---|---|
| ① 指南/规则 | 人读纪律 | `AGENTS-plugin-line-op065op016.local.md`（发布纪律/对外真相/验证纪律/S8） |
| ② skill | 可复用的判断流程 | 待建：`dsh-prepublish-line`（发布前总检）、`dsh-history-rewrite`（历史清理）、`dsh-leak-audit`（泄漏审计） |
| ③ 脚本 | 一次性/常用工具 | `scripts/*.mjs`（闸与工具 20+ 件） |
| ④ 机检 | 有退出码的闸 | **`scripts/gate.mjs`**（一条命令跑九道闸 + 发布后 registry 核验） |
| ⑤ 台账 | 记账 | `工程-插件任务/台账-PROJECT-LEDGER.md`、`暂停交接-*.md`、`待推方案-*.md` |
| ⑥ 设计通则 | 机制怎么长 | M1 归因落结构 / M2 "通过"必须说覆盖哪层 / M3 我记得不算防线闸算 / M4 按后果不按频次 / M5 能机检必须落命令 / M6 证据必须可复算 / M7 例外必须登记+回收 / M8 假绿优先于漏报 |

## 使用
- 发布前：`node scripts/gate.mjs --release`
- 历史/清理类：先干净房 → 再真仓 → 再 `gate.mjs` → 等成员确认
- 泄漏审计：`node scripts/check-published-artifact.mjs`（registry 面）+ `check-external-surface`（发布集）+ `check-git-surface`（GitHub 面）
