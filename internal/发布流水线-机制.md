# 发布流水线机制（开发 → 审核 → 自检 → 独立审核 → 发版）

> 目的：把"靠人记得"变成"靠机制拦住"。**脚本管机械，独立审核管判断。**

## 一、五个阶段

| 阶段 | 谁做 | 产出 | 强制手段 |
|---|---|---|---|
| 1. 开发 | 实现者 | 代码 + 测试（含**负对照**：错误输入必须判红） | 测试必须能失败（本仓要求：每个闸都有负对照用例） |
| 2. 审核（自审） | 实现者 | 变更说明：改了什么 / 为什么 / 影响面 / 未覆盖 | PR 描述或 CHANGELOG 条目 |
| 3. 自检（机械） | **脚本** | 全部闸通过 | `pnpm release:check` 必须 exit 0 |
| 4. 独立审核（判断） | **独立者**（≠ 作者，可以是独立 subagent） | `reviews/<version>.json`（verdict=pass + evidence） | 缺记录 ⇒ 发布被拒（`check-review-record`） |
| 5. 发版（唯一入口） | 实现者 | npm 版本 + `.release-records/<version>-*.json` | 只能走 `pnpm release`；**禁止直接 `npm publish`** |

## 二、脚本清单（全部机械、可复现）

| 闸 | 脚本 | 拦什么 |
|---|---|---|
| 发版纪律 | `scripts/check-release-discipline.mjs` | 版本号只用于功能与修复：**只改文档却升版本 ⇒ 拒**；CHANGELOG 必须有条目 |
| 对外信息 | `scripts/check-external-surface.mjs` | 内部治理叙事 / 机制词 / 本机路径 / 会话标识 出现在**随包发布的内容**里 ⇒ 拒 |
| 核心纯净 | `scripts/check-core-purity.mjs` | 私有能力或平台耦合混入公开面 ⇒ 拒 |
| 发布前闸 | `scripts/prepublish-gate.mjs` | 公开构建产物/发布集一致性、体积超限、禁止文件 ⇒ 拒 |
| 包元数据 | `scripts/check-pkg-meta.mjs` | name/version/engines/exports 缺项或不合规 ⇒ 拒 |
| 契约文档 | `scripts/gen-contracts-doc.mjs --check` | 契约注册表与文档不一致 ⇒ 拒 |
| 全量测试 | `vitest run` | 任何红 ⇒ 拒 |
| 独立审核 | `scripts/check-review-record.mjs` | 无记录 / reviewer=author / verdict≠pass / 无证据 ⇒ 拒 |

## 三、唯一入口

```bash
pnpm release --dry-run     # 只跑全部闸，不发布（CI 用这个）
pnpm release               # 全闸通过 → 发布 → 自动复验 npm 上的 tarball
pnpm release:check         # 只跑三道快闸（纪律 / 对外信息 / 审核记录）
```

`release.mjs` 的行为是**失败即停**，且发布后会**重新下载 npm 上的 tarball 再扫一遍对外信息** —— 防"本地是好的、发出去的不是"。

## 四、制度条款（写入开发规范）

1. **禁止直接 `npm publish`**：一律 `pnpm release`。
2. **版本号纪律**：只有功能或修复才升版本；文档改动随下一次功能版本发布。
3. **独立审核不可省**：作者不能给自己出审核记录；`reviews/<version>.json` 必须含证据（命令/读数/链接）。
4. **负对照**：任何新闸必须附"故意犯错 ⇒ 必须判红"的证明；没有负对照的闸视为未完成。
5. **发布后复验**：以 npm 上的 tarball 为准，不以本地目录为准。

## 五、今日事故与本次机制的对应

| 事故 | 当时缺的闸 | 现在的拦截点 |
|---|---|---|
| 连发 3 个"只改 README"的版本 | 发版纪律闸 | `check-release-discipline`（已负对照验证） |
| 用 revert 提交"撤回"，历史变脏 | 制度（禁止用 revert 掩盖历史） | 本文件 §四.1 + 发版前"工作区必须干净" |
| 对外 README 出现内部叙述 | 对外信息检查只覆盖 retrace，未覆盖本仓 | `check-external-surface`（本仓新增） |
| 发布无独立审核 | 无审核记录要求 | `check-review-record` + `reviews/<version>.json` |


## 边界（2026-10-20 用户裁定）

**拦**：共同体（成员、线名、分工、裁定/派工/台账）· 私有机制（三折/折叠方案/头缓存/水位…）· 私有能力 · 内部落点。
**不拦**：第三方贡献者的 GitHub handle / 公开邮箱 / 提交署名 —— 账号与署名本身就是公开信息；
官方 API/协议名、公开文档术语。
