# 分层与用词 · 定稿（2026-10-21）

> 裁定出处：engineer（comm-1830 回复口径）+ 成员认可；讨论链：comm-1827 / 1829 / 1830 / 1832。

## 一句话
**诊断（diagnose）= contract；治疗（treat/heal）= kit；在线会话写 = retrace。**
「医生」不再单指任何一家；如需对外用 "session doctor"，必须写清 = **诊断 + 治疗合体**。

## 三层定位（对外可用）
| 层 | 对外定位 | 职责 | 铁律 |
|---|---|---|---|
| `dsh-log-contract` | **检验/诊断科** | 判定 = 诊断：规则/契约、`check`（三档 + `--json` + `schemaVersion`）、**`plan`（处方：ops/后置条件/风险/影响面，零 I/O）**、`prewrite`（写前判定）、不变量/负对照 | **永不写盘** |
| `dsh-session-kit` | **主治/外科** | 治疗 = 执行：`heal`、写盘/备份/回滚/写后校验、离线批量/冷备编排、SLA 三档卡、运维 UX | **离线写的唯一入口** |
| `dsh-retrace` | **回溯科/在线门诊** | 在线会话内的回溯/重发/再生/恢复（在线写安全） | **在线会话写的唯一入口** |

## 判据（避免以后争）
1. **谁有判据、谁能判红 → contract**；**谁拿刀 → kit**。
2. 辅助判据：**是否涉及在线会话状态** —— 在线 → retrace；只对文件/事件流 → contract（判定）；需动手 → kit。
3. **写盘单点**：在线会话写 = retrace；离线文件写 = kit；**contract 不写盘**。

## 执行层契约（kit 的 SLA 必须写死五步）
`备份 → 写前校验 → 落盘 → 写后校验（帧级 + fold 重放）→ 失败回滚`

## contract 侧迁移（我方执行）
- A：新增 `plan --json`（纯函数 + `schemaVersion`）；`fix` 默认只出计划（`--apply` 标 deprecate + 告警）
- B：kit 接执行层；`fix --apply` 仅作一版兼容逃生舱
- C：移除写盘 CLI/API；`plan` schema 成为公共契约

## 已知缺口（与 comm-1829 一致）
`check --json` 目前只保证"已读到的事件自洽"，**不保证尾部完整**；下一版增加 `tailStatus: complete|truncated|interrupted|unknown` + 规则与负对照。**在此之前 kit 的 SLA-3 必须保留自有"尾部完整性"格。**

## 文档/命名变更的发布纪律
README 改名（contract = 检验/诊断科；kit = 主治/外科）**随下一次功能版本发**，不单独占版本号。
